      Internet usage through sing-box

      Totals are payload bytes reported by the engine. Per-device, per-node and direct attribution is estimated from one-second connection samples; short flows can be missed. Local AdGuard/Docker traffic and raw forwarding while OFF are excluded. A chain is attributed to its selected exit node, not counted again for each hop.

      LAN devices

      Estimated usage by original client IP, including traffic sing-box routes directly. Only private IPv4 clients intercepted by TPROXY appear. Names and assignments persist by IP.

      Device routes apply after DNS, private-network, custom and Iran rules. Global Default follows the gateway’s selection. Changing an assignment applies immediately and briefly restarts an active proxy.

      Telegram notifications

      Receive engine and subscription alerts. When enabled, only the active node is checked every five minutes; repeated failure alerts are suppressed until recovery.

      Off: connect directly from the Pi. On: use the active node; when automatic selection is offline, use the fastest saved healthy node. Proxy mode never falls back to direct.

      Backup & restore

      Backups contain node credentials, the Telegram token, routing settings and firewall configuration. Store them privately. Restore replaces these settings and restarts the managed engine according to the saved ON/OFF state.

      GeoIP, geosite and routing

      Updates download and validate both rule sets. Applying changes briefly restarts an active proxy. The update schedule runs even when the proxy is off.

      Custom routing rules

      First matching rule wins. Custom rules run before Iran rules, after the gateway’s safety, DNS and private-network rules. Private/local traffic bypassed by nftables is unaffected. Enter one match value per line; use CIDR notation for IPs.
