# DNS و FakeDNS

[صفحهٔ اصلی](../README-fa.md) · [راهنمای انگلیسی](dns.md) · [مسیریابی](routing.md)

DNS را از **تنظیمات ← مسیریابی و DNS** تنظیم کنید. تا زمانی که موتور روشن است،
HooLAN روی **درگاه ۱۰۵۳** با TCP و UDP به درخواست‌ها پاسخ می‌دهد.

## انتخاب سرورها

| تنظیم | کاربرد | نمونه |
| --- | --- | --- |
| سرور DoH از مسیر پروکسی | DNS رمزگذاری‌شده از پروکسی فعال | `https://1.1.1.1/dns-query` |
| سرور DNS مستقیم | DNS برای دامنه‌های محلی و مستثنا | `192.168.3.1` |

برای DoH یک نشانی HTTPS و برای DNS مستقیم یک IP، در صورت نیاز همراه با درگاه،
وارد کنید. نمونه‌ها را با نشانی resolver خودتان جایگزین کنید؛ شبکه به‌صورت
خودکار کشف نمی‌شود. **ذخیرهٔ تنظیمات** تغییرات را اعمال می‌کند.

دامنه‌های محلی و مستثنا از DNS مستقیم استفاده می‌کنند و بقیه از DoH تونل‌شده.
اگر پروکسی نتواند به DoH برسد، جست‌وجوی واقعی ناموفق می‌شود و به مسیر ساده و
رمزگذاری‌نشده برنمی‌گردد.

## نشانی شنود

نشانی پیش‌فرض `127.0.0.1` است. برای دریافت درخواست از دستگاه دیگر، یک IPv4 خصوصی
متعلق به دروازه انتخاب کنید و دسترسی آن دستگاه به TCP/UDP درگاه ۱۰۵۳ را در
فایروال مجاز کنید. نشانی بالادستی DNS به شکل `ADDRESS:1053` است و باید از سمت
فرستندهٔ درخواست قابل دسترس باشد.

فیلد نشانی با روشن‌کردن کلید FakeDNS نمایش داده می‌شود. اگر می‌خواهید FakeDNS
خاموش بماند، کلید را در فرم روشن کنید، نشانی را ویرایش کنید، دوباره خاموش کنید
و سپس ذخیره کنید. پنهان‌شدن فیلد، مقدار ذخیره‌شده یا شنونده را حذف نمی‌کند.
DNS مستقیم نباید درخواست را دوباره به همین شنونده برگرداند.

## FakeDNS

FakeDNS به دامنه‌های پروکسی‌شده IPv4 مجازی می‌دهد. هنگام اتصال دستگاه، HooLAN
دامنهٔ اصلی را بازیابی می‌کند، نشانی واقعی را با DNS رمزگذاری‌شده می‌یابد و
قواعد مسیریابی را اعمال می‌کند. دامنه‌های مستثنا پاسخ واقعی DNS مستقیم دارند.

- محدودهٔ نشانی‌های مجازی `198.18.0.0/15` است.
- فقط دستگاه‌هایی که اتصالشان از TPROXY در HooLAN عبور می‌کند باید پاسخ مجازی
  بگیرند. خود دروازه و دستگاه‌هایی که رهگیری نمی‌شوند به DNS واقعی نیاز دارند.
- پاسخ AAAA و HTTPS/SVCB خالی است. ترافیک IPv6 یا DoH/DoT داخلی برنامه‌ها
  به‌صورت خودکار رهگیری نمی‌شود.
- پاسخ A مجازی با اعتبارسنجی DNSSEC رکورد اصلی سازگار نیست.
- هنگام روشن یا خاموش‌کردن FakeDNS، حافظهٔ نهان DNS دستگاه‌ها را پاک کنید.

برای تفکیک DNS با پاسخ واقعی، FakeDNS را خاموش نگه دارید.

## تطبیق قواعد و راه‌اندازی

قواعد دامنهٔ سفارشی، مجموعه‌قواعد و پیش‌تنظیم ایران به‌ترتیب تنظیم‌شده اعمال
می‌شوند: direct یعنی DNS مستقیم، proxy یعنی DoH تونل‌شده و reject یعنی رد
درخواست. خاموش‌کردن پیش‌تنظیم ایران تطبیق DNS آن را هم غیرفعال می‌کند. پسوندهای
`lan`، `local` و `home.arpa` و محدوده‌های DNS معکوس مستقیم می‌روند.

برای تطبیق IP و GeoIP ابتدا پاسخ رمزگذاری‌شدهٔ DoH ارزیابی می‌شود. اگر قاعدهٔ
مستقیم تطبیق داشت، درخواست جدید به DNS مستقیم می‌رود؛ وگرنه همان پاسخ استفاده
می‌شود. مجموعه‌قواعد سفارشی ممکن است IP داشته باشند و به ارزیابی نیاز دارند.
قواعد دامنه‌ای که زودتر تطبیق کنند، بدون پرس‌وجوی DoH به DNS مستقیم می‌روند.

برای جلوگیری از وابستگی دوری، نام سرور پروکسی، میزبان دریافت مجموعه‌قواعد و
راه‌اندازی DoH مبتنی بر نام، از DNS مستقیم استفاده می‌کنند. نشانی‌های مبتنی بر
IP این وابستگی را کاهش می‌دهند. اعتبارسنجی گواهی HTTPS روشن می‌ماند.

DoH از پروکسی سراسری فعال، از جمله زنجیره یا گروه انتخاب‌شده، استفاده می‌کند؛
تنظیم خروجی هر دستگاه مسیر DNS جداگانه ایجاد نمی‌کند.

## بررسی عملکرد

به‌جای `GATEWAY_IP` نشانی شنود ذخیره‌شده را بگذارید:

</div>

```bash
dig @GATEWAY_IP -p 1053 example.com A
dig @GATEWAY_IP -p 1053 example.com A +tcp
sudo ss -lntup '( sport = :1053 )'
```

<div dir="rtl">

با FakeDNS خاموش، پاسخ واقعی دریافت می‌کنید. با FakeDNS روشن، دامنهٔ غیرمستثنا
باید نشانی مجازی بگیرد. یک دامنهٔ مستثنا را هم آزمایش کنید.

آزمایش را از فرستندهٔ واقعی DNS هم انجام دهید؛ پاسخ روی خود دروازه، دسترسی
دستگاه دیگر را ثابت نمی‌کند. برای timeout فقط از راه دور، نشانی شنود، مسیر و
فایروال را بررسی کنید. اگر فقط دامنه‌های غیرمستثنا مشکل دارند، پروکسی فعال و
سرور DoH را بررسی کنید. پاسخ DNS به‌تنهایی مسیر اتصال بعدی دستگاه را ثابت نمی‌کند.

## حافظهٔ نهان و خاموش‌کردن

توقف موتور درگاه ۱۰۵۳ را هم متوقف می‌کند، حتی اگر FakeDNS خاموش باشد. پیش از
توقف، درخواست‌کنندگان را به resolver واقعی و در دسترس منتقل کنید. اگر FakeDNS
روشن بوده، cacheهای DNS را پاک و برنامه‌ها را دوباره متصل کنید؛ نشانی مجازی
نمی‌تواند مثل مقصد اینترنتی عادی forward شود.

نگاشت‌ها معمولاً در `/var/lib/hoolan/cache.db` باقی می‌مانند. این فایل را در
راه‌اندازی مجدد حفظ کنید. فایل cache در ZIP پشتیبان نیست؛ پس از بازیابی روی
میزبان دیگر یا از دست‌رفتن نگاشت‌ها، cache دستگاه‌ها را پاک کنید. TTL پاسخ
مجازی ۶۰ ثانیه است ولی برنامه‌ها ممکن است مدت بیشتری آن را نگه دارند.

جدول محافظ `inet hoolan_fakedns` مقصدهای مجازی را در forwarding و خروجی میزبان
مسدود می‌کند و پس از خاموش‌شدن هم باقی می‌ماند. افزایش شمارندهٔ آن می‌تواند
نشانهٔ عبورنکردن از TPROXY یا پاسخ‌های قدیمی باشد. خاموش‌کردن فقط FakeDNS،
شنوندهٔ DNS واقعی را متوقف نمی‌کند.

مصرف دستگاه‌ها بر اساس IP اصلی تخمین زده می‌شود. برای تشخیص مسیر اتصال‌های
مجازی، نمونه‌های موتور با اطلاعات محدود nftables ترکیب می‌شوند. در نبود
اطلاعات کافی، سقف سخت‌گیرانه‌تر اعمال می‌شود؛ اتصال‌های کوتاه ممکن است در
نمونه‌برداری دیده نشوند.

## API

فیلدهای `tunneled_doh`، `direct_dns` و `fake_dns` در `GET/PUT /api/settings`
استفاده می‌شوند و در `state.json` و پشتیبان ذخیره می‌شوند. فیلدهای ارسال‌نشده
حفظ می‌شوند. `dns_server` قدیمی به‌عنوان نام جایگزین DNS مستقیم پذیرفته می‌شود.
قالب تولیدشده برای sing-box نسخهٔ ۱٫۱۴ به بعد است.
